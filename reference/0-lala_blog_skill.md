# 라라 블로그 글쓰기

**두 가지 원칙이 이 스킬의 전부다** (스레드 스킬에서 검증된 것):

1. **파라미터는 이 문서에 없다.** 위키에 있고, 매번 읽어서 쓴다.
2. **기억한 파라미터로 쓰지 말고, 진짜 발행글을 옆에 놓고 쓴다.**
   요약은 방향만 주고 온도는 못 준다. 온도는 원문에만 있다.

## 확정된 전제 (결론만 — 경위·실측 근거는 `HISTORY.md`, 평소엔 열지 않는다)

1. **목적 = 처음 오는 독자의 유입** (2026-08-11 확정). 유입의 본체는 두 갈래다:
   - **네이버 모바일 홈판(MY피드)** — 2026-10-30 관리자 통계 전수 분석에서 수천 회 이상 글의 80.32%.
     규칙은 아래 「네이버 홈판 … 최적화 규칙」.
   - **키워드 검색** — 40~130회 수준. 1단 책 후기(가설: 한 책을 2편, 각 1,500자+ — n=1이라 검증 대상),
     2단 경력(영업·SCM) 정보성 글. 경력글은 스레드·개인 브랜딩과 소재가 겹치니 착수 전 확인.
   - 문체는 266편에서 가져오되, 독자 전제("나를 아는 사람들")는 버린다.
2. **문체 위키 5차원 사용법** (2026-08-11 판정):
   일상→통찰 변환·문장 리듬은 그대로 / 시각·편집은 「4. 제목·부제 패턴」만 폐기 /
   카테고리 스펙트럼의 **분량 수치는 믿지 않는다**(→ `python scripts/analyze_blog.py --section lengths`) /
   독자 친밀도는 방향 반전 — 「기법 2: 닉네임 호명」 폐기, 「기법 1: 비밀 보존」 강화.
3. **안전 등급표 완료** — 원본 `concepts/라라-블로그-안전등급.md` (0단계가 읽는다).
   A등급은 책 후기·자작시·투자관련공부 3개뿐, 격리 11편(정박용 읽기 O, 인용 X).
   `내 안의 생각들`의 격리 6편은 감정 온도가 가장 높은 글이라, 온도만 보고 정박글을 고르면 금지선을 밟는다.
4. **실측 도구** — `python scripts/analyze_blog.py --section verify`가 위키 수치를 재현한다 (2026-08-12 30/30 PASS,
   2026-11-05 재실행 19/30 — 원인 미확인, 쓰기 전에 FAIL 항목을 확인할 것).
   사인오프는 237편 중 164편(69%).
   `check_draft.py`는 위키 표를 파싱하지 않고 `analyze_blog.py`를 모듈로 불러 실측 중앙값·안전 신호
   정규식을 재사용한다. 어미 경향 표는 재현 명령이 없는 미검증 표다.

## 0단계 — 안전 게이트 (건너뛰지 말 것)

**두 페이지를 읽는다. 표를 여기 옮겨 적지 않는다 — 위키가 원본이다.**

1. `templates/llm-wiki/wiki/entities/라라.md` 「⚠️ 페르소나 노출 금지선」 — 안전선 문구
2. `templates/llm-wiki/wiki/concepts/라라-블로그-안전등급.md` — 등급표·격리 목록·공통 금지

블로그는 스레드와 달리 **판정이 2축이다** (IN 원천 / OUT 출력). 같은 문장도 채널이
바뀌면 노출 범위가 달라진다. **블로그에 이미 발행된 내용이라는 것은 다른 채널로 옮겨도
된다는 뜻이 아니다.**

매 글마다 이 순서로 통과시킨다:

1. **소재의 카테고리를 정하고 등급을 읽는다.** D면 여기서 멈춘다
2. **정박 대상이 격리 목록에 있는지 확인한다.** 있으면 읽기만 하고 인용하지 않는다
3. **나갈 채널을 확인한다.** B등급 소재는 블로그 밖으로 나가지 않는다
4. **공통 금지 3종을 검사한다** — 타인 닉네임 / 격리글 인용 / B등급 채널 이탈

**등급이 없으면 쓰지 말고 먼저 알린다.** 표에 없는 것은 아직 허용된 것이 아니다.
추측으로 등급을 만드는 것이 이 게이트가 막으려는 바로 그 실패다.

## 1단계 — 문체 파라미터 로드

읽을 것: `templates/llm-wiki/wiki/concepts/라라-문체.md`와 그 하위 페이지.

**읽지 말 것**: 스레드 문체 페이지. 별개 체계이고 블로그에 적용하면 틀린다
(스레드에는 사인오프가 0%인데 블로그는 정형구다).

**신변 사실은 지어내지 않는다.** 위키에 없는 사실이 필요하면 쓰지 말고 본인에게 묻는다.

## 2단계 — 진짜 발행글 정박 ★

초안을 쓰기 전에 소재와 가까운 **실제 발행글 2~3편**을 `raw/`에서 찾아 눈앞에 놓는다.

이 단계가 제일 중요하다. 스레드 스킬의 첫 두 초안이 자기점검을 통과했는데도 문체가
어긋나 있었고, 원인은 파라미터 요약만 보고 쓴 것이었다.

## 3단계 — 카테고리 확정 (유형 선택)

**카테고리 = 유형.** 스레드의 유형 5개(통념 반박·장면 관찰·대구 명제·독백 다짐·질문 참여)에
해당하는 것이 블로그에서는 카테고리 10개(A/B등급 8개 + D등급 2개, 등급표는 0단계)다.
`concepts/라라-카테고리-스펙트럼.md`에서 소재에 맞는 카테고리를 고른다.

**단, 그 페이지의 분량 표(KB/자)는 믿지 말 것** — 이미 실측과 어긋난다고 확인됐다
(「확정된 전제」 2번·4번). 분량 감은 여기서 잡지 않고 5단계에서
`analyze_blog.py --section lengths`로 잡는다. 톤·기능 설명(응축↔서술 축, 외부↔내면 축,
카테고리별 톤 디테일)은 분량과 별개로 유효하다.

유입이 목적(「확정된 전제」 1번)이므로 카테고리 선택은 안전 등급과도 맞물린다 — A등급(책 후기·
자작시·투자관련공부)이 검색 축과 가장 잘 맞는다. **책 후기**를 고를 경우, 검색 축 1단
검증 과제(메트로폴리탄 패턴 재현 시험 — 같은 책을 2편으로, 각 1,500자+)를 이번에 시도할지
이 시점에 정한다.

## 4단계 — 사인오프 여부 결정

**매번 결정한다. 자동 부착 금지** — 266편 전부가 아니라 8개 카테고리 기준
164/237편(69%)만 쓴다(재현: `analyze_blog.py --section signoff`). 다는 게 아니라는 걸
알면서 매 글에 붙이면 오히려 그 규칙성이 생성된 티를 낸다.

붙이기로 했으면 변형 없이 정형구 그대로 쓴다 —
`"나는 매일(또는 오늘도) 나만의 출발선에 다시 선다(또는 섭니다)."`
(「라라-시각-편집」 1: "변형 없음: 다른 표현으로 바꾸지 않음"). `check_draft.py`가
`출발선`은 있는데 정형 패턴과 안 맞으면 경고한다.

## 5단계 — 초안 작성

파라미터는 1단계 페이지를, 온도는 2단계 원문을 따른다. 가장 자주 틀리는 것만 짚는다:

1. **길이**: 카테고리별 실측 중앙값을 따른다 (`analyze_blog.py --section lengths`).
   위키 표(`라라-카테고리-스펙트럼`)의 KB 값을 그대로 목표 분량으로 삼지 말 것 —
   책 후기 항목만 해도 위키값(4-7KB)이 실측(2.18KB)의 약 3배였다.
2. **존댓말은 `-요`/`-습니다` 우세가 기본.** 단 회사 이야기 카테고리는 1인칭 해체체
   (`~다`)가 우세하다고 관찰됨 — 단, 이 표(「라라-문장-리듬」 카테고리별 어미 경향)는
   분량 표와 달리 재현 명령이 없는 **미검증** 표다. 참고만 하고 원문 대조를 우선한다.
3. **양가성을 해소하지 말고 둘 다 인정한다** (`그래도`·`하지만`·`한편으론`·`~기도 합니다`) —
   「라라-일상-통찰-변환」 3단. 통찰을 단정형으로만 밀면 훈계처럼 읽힌다.
4. **빈 줄로 호흡을 만든다.** 1-3문장 단락, 문장 사이 줄바꿈, 단락 사이 빈 줄
   (+ 네이버 에디터 관행인 ZWSP 줄 — 로컬 마크다운 초안 단계에서는 생략 가능,
   발행 시 네이버 에디터가 자동 처리하는 부분이라 초안 검증 대상은 아니다).
5. **타인 닉네임을 새 글에 쓰지 않는다** — 0단계 공통 금지 1번. 「라라-독자-친밀도」
   「기법 2: 닉네임으로 신호 보내기」는 검색 유입 목적과 충돌해 폐기 판정된 기법이다.
6. **신변 사실을 지어내지 않는다.** 위키에 없는 사실이 필요하면 쓰지 말고 사용자에게 묻는다.
7. **제목을 억지로 정보성으로 만들지 않는다.** 237편 중 216편은 애초에 검색 수요 0인
   추상명사형 제목이었고 그게 정상이다 — 정보성 표지(후기/방법/추천 등)를 강제로
   욱여넣으면 오히려 코퍼스에서 벗어난 글이 된다. 책 후기가 아니면 짧은 제목 형식
   (「라라-시각-편집」 4의 형식 부분)을 유지해도 된다.
8. **한 비유·어휘를 굴리지 않는다.** 같은 어휘가 3회 나오면 생성된 티가 난다.
9. **항목을 나열할 때 가운데점(·)으로 잇지 않는다.** "정보·경험·통찰"처럼 붙이면 생성된
   티가 난다. 쉼표로 풀거나 "~하고 ~하고" 같은 자연스러운 접속으로 쓴다.

## AEO/GEO/NEO — 검색·AI 인용 신호 (책 후기·투자관련공부 중심)

검색 유입이 이 블로그의 확정 목적(「확정된 전제」 1번)이므로, **책 후기·투자관련공부**
카테고리(검색축 1·2단)에는 아래 신호를 얹는다. 자작시·감성 에세이류에는 억지로 적용하지
않는다. 출처: `fire-your-seo-agency` 저장소의 `references/aeo.md`·`geo.md`·`neo-naver.md`.

**글 안에서 할 수 있는 것 (문체를 안 건드리는 범위):**

- **첫 문단에서 방향을 먼저 준다.** 도입 2~3문장 안에 이 글이 뭘 다루는지 드러낸다 —
  라라 문체(장면 시작)와 공존 가능: 장면 한 줄 뒤 바로 주제를 얹는다.
- **문장이 맥락 없이도 사실을 말하게 한다.** "위에서 말한 그 책" 대신 "《메트로폴리탄
  미술관의 경비원입니다》는" 식으로 문단마다 주어를 다시 밝힌다 — 발췌돼도 뜻이 산다.
- **기준·날짜를 붙인다.** 책 후기면 읽은 시점, 투자관련공부면 수치에 기준일. 없는 기준을
  지어내지 않는다 — 위키·사용자 확인 없이 날짜를 만들지 않는다.
- **제목에 검색 신호가 있으면 살린다** (5단계 7번과 동일 원칙 — 억지로 만들지 않는다).
  책 제목·저자명이 제목에 그대로 들어가면 그것으로 충분하다.

**하지 않는 것 (이 블로그의 안전선·페르소나와 충돌):**

- FAQ 블록 강제 삽입 — 라라 문체(문장 리듬·행갈이)와 안 맞고, 에세이형 글에 붙이면 생성
  티가 난다. 투자관련공부처럼 정보 밀도가 실제로 높은 글에서만, 그것도 자연스러우면 고려.
- 운영자 신원 공개·연락처 노출 (E-E-A-T 신호) — 0단계 안전 게이트와 정면 충돌. 시도하지 않는다.
- 구조화 데이터(JSON-LD)·사이트맵·서치어드바이저 등록 — 이 스킬(글쓰기) 범위 밖. 발행
  플랫폼 쪽 작업이다.

**검증**: 발행 후 네이버 통계에서 해당 글의 유입 검색어가 잡히는지 7단계 되먹임에 기록한다
(기존 규칙). AI 브리핑 인용 여부까지 보고 싶으면 네이버 앱에서 그 검색어를 직접 검색해
출처 칩에 이 블로그가 뜨는지 확인한다.

## 네이버 홈판(MY피드·경제판) 조회수 폭발 최적화 규칙 (실측 기반)

2026-10-30 네이버 블로그 관리자 통계(admin.blog.naver.com) 전수 분석 결과, **수천 회 이상 폭발한 글들의 80.32%는 검색 유입이 아니라 '네이버 모바일 홈판(MY피드 추천)'**이었다. 단순 키워드 검색 유입은 40~130회 수준(중박)에 머무른다. 따라서 대박 트래픽의 본체는 네이버 AI 추천 알고리즘의 픽을 받는 것이며, 아래의 **소재·제목·시의성·본문 4대 폭발 공식**을 엄격히 준수한다.

### 1. 소재 선별 공식 (내 지갑·내 세금·장바구니 체감형)
- **필수 선정 소재 (폭발군)**:
  - 독자의 통장 잔고와 직결되는 체감 이슈만 터진다.
  - **환급 / 파격 할인**: 온누리상품권 30% 환급, 지역화폐 인센티브, 마트 반값 행사
  - **세금 유예 / 감면 / 공제**: 가상자산 소득세 유예, 연말정산 소득공제 황금비율, 상속·증여세 절세
  - **정부 지원금 / 보조금**: 전기차 보조금 전환지원금 신설, 청년·육아 지원금
- **배제 및 지양 소재 (저조군)**:
  - 거시 경제 담론: 미국 FOMC 기준금리 전망, 환율 변동 매크로 분석
  - 단순 주식 시황: 코스피/코스닥 박스권 등락, 외국인/기관 수급 분석
  - 실생활 체감 불가 B2B 제도: 일반 소비자가 즉시 혜택을 보기 어려운 정책

### 2. 제목 3단 조합 공식 (25자 피드 압축 & CTR 극대화)
모바일 홈판(MY피드) 카드는 제목이 앞 **25~30자 내외에서 말줄임표(...)로 잘린다.**
제목 조합 공식:
```
[핵심 키워드/타깃] + [확정/감정/의문 훅] + [(+구체적 숫자 혜택)]
```
실측으로 입증된 3대 검증 패턴:
1. **A형 (키워드 + 확정 훅 + 숫자 혜택)**:
   - `온누리상품권 추석 할인 확정 (+전통시장 환급 30%)` (5,667회)
   - 핵심 키워드 전면 배치 + `확정` 표지 + 괄호 속 명확한 금전적 수치 이득(`30%`).
2. **B형 (감정/공감 훅 + 키워드 + 확정/유예)**:
   - `코인만 왜?, 가상자산 과세 2027년 시행 확정` (4,162회)
   - 독자의 불만·호기심을 찌르는 짧은 의문 훅(`코인만 왜?`) + 정책 핵심 키워드 + `확정`.
3. **C형 (키워드 + 개편 훅 + 혜택 의문)**:
   - `전기차 보조금 2026년 하반기 개편, 전환지원금 신설?` (2,000회+)
   - 구매 예정자 필수 키워드 + 정책 시기 명시 + 새로운 금전 혜택에 대한 질문 훅(`신설?`).

**제목 작성 3대 체크리스트**:
- [ ] 제목 앞 15자 안에 핵심 검색 키워드/타깃이 배치되었는가?
- [ ] 클릭을 유발하는 훅(`확정`, `왜?`, `신설?`, `총정리`, `갈아타기`)이 포함되었는가?
- [ ] 괄호`()` 또는 숫자(`30%`, `반값`, `1인당 00만원`)로 구체적 혜택이 직관적으로 보이는가?

### 3. 시의성 & 배포 타이밍 공식 (Timing & Shelf-life)
- **정책 / 세제 / 정부 지원금**:
  - 국회 통과, 정부 발표 당일~익일 오전 집중 발행한다.
  - 뉴스 기사보다 한발 앞서 '직장인·소비자 체감형 요약'으로 치고 나가야 홈판 알고리즘이 우선 추천한다 (`확정`, `시행` 키워드 선점).
- **축제 / 할인 행사 / 시즌 이벤트 (검색 유입 타깃)**:
  - 행사 시작 **2~3일 전(D-2 ~ D-3)** 사전 발행이 필수다 (당일 발행은 검색 상단 선점 불가).
  - 필수 기재: 날짜, 무료 입장, 주차 꿀팁, 셔틀버스, 할인 품목 등 방문자 실전 편의 정보.

### 4. 본문 구조 & 체류시간 극대화 (D.I.A.+ 충족)
1. **도입부 첫 120자 리드문 (Lead-in Hook)**:
   - 네이버 홈판 피드 텍스트 스니펫(100~150자) 자동 추출 대응.
   - 인사말·잡담 전면 배제. 독자가 얻을 핵심 이득과 결론을 첫 2문장(120자 내외)으로 압축하여 제시.
2. **대표 인포그래픽 썸네일 필수**:
   - 피드 카드 썸네일 노출을 위한 3D 일러스트 또는 텍스트 중심 깔끔한 인포그래픽 이미지를 글 최상단에 배치.
3. **1인칭 직장인 실전 시뮬레이션 표 (필수)**:
   - 단순 보도자료/뉴스 요약은 AI 중복 문서로 판정되어 홈판 추천에서 즉시 제외된다.
   - 반드시 **"직장인 연봉 5천 기준 세후 계산", "100만원 사용 시 환급 비교표"**처럼 직접 계산·대입한 실전 비교 데이터를 1개 이상 삽입한다.
4. **모바일 최적화 여백 및 서식**:
   - 스마트폰 한 화면 기준 2~3줄 단위 줄바꿈, 단락 간 빈 줄, 굵은 글씨 소제목, 3줄 요약 박스로 체류시간을 극대화한다.
5. **발행 태그 10개 전략**:
   - 글 말미에 네이버 모바일 검색 수요가 명확한 스마트블록 연관 키워드(10개 이내)를 지정한다.

## 6단계 — 검증

**먼저 기계로 돌린다.**

```bash
python .claude/skills/lala-blog/check_draft.py drafts/blog/<파일>.md
```

카테고리별 분량·어미 경향·사인오프 변형·양가성 접속사 유무·단락 리듬·격리 키워드
(Tier 1/2)·닉네임 신호·어휘 반복을 검사한다. `[오류]`는 `category:` 미기재나 D등급
카테고리 오기재처럼 구조적 실수만 잡는다 — 안전 등급 판정 자체는 사람이 0단계로 한다.
`[주의]`는 판단한다. 검사기 설계 근거는 `HISTORY.md` 5번.

**기계가 못 잡는 것만 사람이 본다** (항목을 늘리지 말 것):

- [ ] 소재의 카테고리·등급을 0단계 게이트로 다시 통과시켰나 (D면 중단, 격리 목록
      11편이면 인용 금지, B등급이면 다른 채널로 안 나감)
- [ ] 신변 사실이 전부 위키에 근거가 있나 (지어낸 디테일 없나)
- [ ] 기존 발행글과 같은 소재를 재탕하고 있지 않나

## 7단계 — 되먹임

**초안은 `raw/`에 넣지 않는다.** `raw/`는 발행 원문 아카이브다. 섞으면 소스 레이어가
오염되고 `lint_wiki.py`의 raw 커버리지 검사가 계속 미인제스트로 잡는다.

- 초안 저장: `drafts/blog/YYYY-MM-DD-<짧은슬러그>.md`
- 개정할 때는 구버전을 코드펜스로 남기고 무엇이 왜 틀렸는지 적는다
  (검사기는 첫 `---`에서 멈춘다)
- 발행 후 원문은 다음 아카이브 갱신 때 `raw/`로 들어온다

**문체 페이지를 갱신해야 하는 경우**: 위키에 없는 패턴을 사용자가 요구하거나 교정했다면
새 파라미터다. 해당 `concepts/라라-*` 페이지를 갱신하고 `updated`를 오늘로 스탬프,
`## Change Log`에 한 줄 추가한다. **교정이 검색으로 확인 가능한 것이면 `analyze_blog.py`로
실측해서 숫자를 함께 적는다** — 인상으로 적으면 다음 세션이 그 인상을 사실로 믿는다.

문체 페이지를 건드렸으면 마지막에 검증한다:

```bash
python scripts/lint_wiki.py --root templates/llm-wiki
```

**검색 축 실험 결과 기록**: 3단계에서 책 후기를 검색 축 1단 검증용으로 썼다면, 발행 후
네이버 통계에서 유입 검색어가 잡히는지 확인한다. 결과는 이 스킬 문서가 아니라
`lala-thread-writer`의 `wiki/workflows/라라-블로그-라이터.md`(원설계 문서)에 남긴다 —
성과 데이터는 그쪽에 쌓아야 다음 세션이 n=1에서 넘어갈 수 있다.

## 하지 말 것

- 스레드 문체 페이지를 참조하는 것
- 파라미터를 이 문서나 검사기에 복제하는 것 (위키가 원본이다)
- 2단계를 건너뛰고 파라미터 요약만으로 쓰는 것
- 등급을 확인하지 않고 소재를 쓰는 것. 표에 없으면 허용이 아니라 **중단**이다
- 격리 목록 11편의 소재·문장을 인용하는 것 (읽는 것은 허용, 가져오는 것은 금지)
- B등급 소재를 스레드·쇼츠로 옮기는 것
- 사인오프를 매 글에 자동으로 붙이는 것 (4단계) — 실측은 69%다
- 제목에 정보성 표지를 억지로 넣는 것 (5단계) — 216/237편은 검색 수요 0인 제목이 정상이었다
- 6단계 사람 점검 항목을 늘리는 것 — 검사할 수 있는 건 스크립트로 보낸다
- **스레드 글을 여기서 쓰는 것** — `lala-thread-writer` 로 간다
